# kinn-kinn.com 更新ガイドライン

この文書は、プロジェクトと活動履歴を手作業で安全に更新するための運用手順です。外部APIからプロジェクト一覧を自動生成せず、リポジトリ内のデータファイルを正とします。

## 更新元

| 内容 | 編集するファイル | 原則 |
| --- | --- | --- |
| プロジェクト一覧・Pinned Projects | `src/data/projects.ts` | 1プロジェクトにつき1オブジェクト |
| プロジェクト画像 | `public/projects/` | 1200×675の軽量WebP |
| Activity | `src/data/activities.ts` | Release / Article / Mention / Adoption / Researchを1配列で管理 |
| 氏名・プロフィールリンク | `src/config.ts` | 共通設定として管理 |

`src/content/projects/`のMarkdownやGitHub API同期は使用しません。表示に必要な情報は上記のTypeScriptファイルへ明示的に記述します。

## プロジェクトを追加・更新する

`src/data/projects.ts`の`projects`へオブジェクトを追加します。

```ts
{
  id: "project-slug",
  title: "表示名",
  description: "一覧で内容が分かる1文",
  publishedAt: new Date("2026-08-23T00:00:00+09:00"),
  featured: false,
  order: 12,
  image: "/projects/project-slug.webp",
  imageAlt: "プロジェクト名のGitHubプレビュー",
  tags: ["TypeScript", "Astro"],
  github: "https://github.com/owner/repository",
  demo: "https://example.com/",
  zenn: "https://zenn.dev/kinnkinn/articles/article-id",
  language: "TypeScript",
  languageColor: "#3178c6",
  stars: 0,
  demoLabel: "Open app",
  overview: ["Project Pageに表示する概要。"],
  highlights: ["主な特徴。"],
  impact: ["外部での採用や反響。"],
  schemaType: "SoftwareApplication",
}
```

### 各フィールドのルール

- `id`: 小文字のkebab-caseで一意にします。Activityの`project`から参照されるため、公開後は原則変更しません。
- `title`: サービスや成果物の正式な表示名を使います。
- `description`: 何をするものか、対象、特徴が1文で分かる長さにします。
- `publishedAt`: 初回公開日をJST付きISO形式で記述します。
- `featured`: トップページへ固定表示する場合だけ`true`にします。Pinned Projectsは最大4件を想定しています。
- `order`: Projectsページの表示順です。値を重複させず、並べたい順に連番を付けます。
- `image`: `public/projects/`に置いた1200×675のWebPを`/projects/ファイル名.webp`で参照します。
- `imageAlt`: 画像が見えなくても内容が分かる日本語にします。
- `tags`: 検索対象です。主要技術と用途を2〜4件に絞ります。
- `github`: 必須です。リポジトリの正規URLを指定します。
- `demo` / `zenn`: 存在する場合だけ追加します。カード上に外部リンクとして表示されます。
- `language` / `languageColor` / `stars`: トップページのPinned Projectsでも使われる表示情報です。
- `demoLabel`: Project PageのDemoボタンに表示する短い文言です。
- `overview`: Project Pageの概要です。主要プロジェクトは背景や設計を2段落程度で記述します。
- `highlights`: 主要機能や技術的な特徴を3件程度記述します。
- `impact`: 外部採用、派生、記事の反響がある場合だけ記述します。
- `schemaType`: Webアプリは`SoftwareApplication`、ライブラリやコード主体の成果物は`SoftwareSourceCode`を指定します。

画像は`npm run images:projects`で公開中の元画像から再生成できます。元画像URLや加工方法を変更する場合は`scripts/build-project-images.mjs`を更新します。カードへはGIFや巨大な原寸画像を直接指定せず、1200×675へ縮小したWebPを使ってください。目安は1枚150 KB以下、全11枚で1 MB以下です。

## Activityを追加・更新する

`src/data/activities.ts`の`activities`へ、新しいものが上になるよう追加します。

```ts
{
  date: "2026-08-23",
  type: "Release",
  title: "プロジェクトを公開",
  description: "何が起きたかを補足する1〜2文",
  url: "https://example.com/",
  project: "project-slug",
}
```

種類は次の基準で選びます。

- `Release`: 新規公開、正式リリース、大きなバージョン更新
- `Article`: 自分が公開した記事
- `Mention`: 外部メディアや第三者による紹介・言及
- `Adoption`: 外部プロジェクトへの採用、移植、派生、公式一覧への掲載
- `Research`: 検証、実験、調査、技術的成果

`date`は`YYYY-MM-DD`、`project`は`projects.ts`に存在する`id`を使います。同日に複数件ある場合も別項目として記録します。リンク先がなければ`url`は省略できます。

## 更新手順

1. `main`を最新化し、作業ブランチを作ります。
2. データファイルを編集します。
3. 画像を追加・変更した場合は`npm run images:projects`を実行します。
4. `npm run dev`でカード、リンク、検索、スマートフォン幅、ライト・ダークテーマを確認します。
5. `npm run build`と`git diff --check`を実行します。
6. Pull Requestに変更内容と確認結果を書き、Cloudflare Pagesのプレビュー成功後にマージします。
7. マージ後、`https://kinn-kinn.com/`、`/projects/`、各Project Page、`/writing/`、`/activity/`を本番で確認します。

## レビュー用チェックリスト

- [ ] `id`と`order`が重複していない
- [ ] 日付順と表示順が意図どおり
- [ ] GitHub、Demo、Zenn、Activityのリンクが開く
- [ ] 外部画像が表示され、`imageAlt`が適切
- [ ] プロジェクト名・説明・タグで検索できる
- [ ] Pinned Projectsが4件以内
- [ ] `npm run build`が成功する
- [ ] Cloudflare Pagesのプレビューと本番デプロイが成功する
